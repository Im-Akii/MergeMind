=====================================================================
 MergeMind - set it up on YOUR OWN GitHub repository
=====================================================================

MergeMind is a GitHub agent. When someone opens an issue in your repo it
investigates the code (NVIDIA Nemotron + entire-graph), offers the reporter
the chance to fix it, reviews their pull request against your code, never
leaks secrets or private files to them, and merges only after YOU (a
maintainer) approve.

It runs for free on GitHub Actions in your repository. No server needed.

Time needed: about 20 minutes.

---------------------------------------------------------------------
 WHAT YOU NEED
---------------------------------------------------------------------

  1. A GitHub repository you own or administer (public or private).
     Public repos get GitHub Actions minutes for free.
  2. A Python project tested with pytest. MergeMind's test workflow runs
     `pip install -e .` and `python -m pytest`. (Other languages work if
     you adapt the workflow in step 3; keep the job names `tests` and
     `regression`.)
  3. An NVIDIA API key (free): https://build.nvidia.com
     -> sign in -> pick any Nemotron model -> "Get API Key".
  4. Optional: a neatlogs API key (tracing dashboard): https://app.neatlogs.com
  5. On your computer, only for step 3: git and Python 3.12+ with `uv`
     (https://docs.astral.sh/uv/) or `pip`.

---------------------------------------------------------------------
 STEP 1 - Create a GitHub token for MergeMind
---------------------------------------------------------------------

MergeMind posts comments, reviews PRs and merges using this token.

  1. Open https://github.com/settings/personal-access-tokens
     -> "Generate new token" (fine-grained).
  2. Token name: mergemind. Expiration: your choice.
  3. Repository access: "Only select repositories" -> pick YOUR repo.
  4. Repository permissions:
       Contents ............ Read and write
       Issues .............. Read and write
       Pull requests ....... Read and write
       Commit statuses ..... Read and write
       Administration ...... Read and write  (only needed for
                                               access.mode: collaborator;
                                               not needed for fork mode)
       Actions ............. Read-only
       Metadata ............ Read-only (selected automatically)
  5. "Generate token" and copy it somewhere safe. You'll paste it in step 4.

Note: comments MergeMind posts appear under the account that owns this
token. Use a separate bot account if you don't want them under your name.

---------------------------------------------------------------------
 STEP 2 - Decide how contributors get access (the policy file)
---------------------------------------------------------------------

Create the file .github/mergemind.yml in your repo. A good start:

    autonomy: merge                 # observe | suggest | invite | merge
    maintainers: [your-github-username]
    access:
      mode: fork                    # fork (safest) | collaborator
      ttl: 3d                       # how long a contributor keeps the issue
      checkin_at: 50%               # MergeMind checks in halfway
      min_account_age: 30d          # refuse brand-new GitHub accounts
    pr:
      require_regression_test: true # a new test must fail without the fix
      allow_out_of_scope: flag      # flag | block
      merge_method: squash          # squash | merge | rebase
      ci_timeout: 30m
      post_merge_watch: 30m         # watch main's tests after merging
    guard:
      sensitive_paths: [".env*", "**/.env*", "**/*.pem", "**/*.key",
                        "**/secrets/**", "deploy/**", "infra/**"]

What the settings mean:

  autonomy   observe  = only watches, writes nothing
             suggest  = triages and comments, never grants access
             invite   = also offers/grants contributor access
             merge    = also merges, but ONLY after a maintainer types
                        /mergemind approve on the pull request
  mode       fork          = contributors fork and open a PR. They never get
                             write access. Recommended for public repos.
             collaborator  = contributors are invited with push access for
                             `ttl`, then removed automatically. Requires the
                             Administration permission (step 1) and a
                             protected main branch (step 5).
  sensitive_paths  files MergeMind never shows to the AI and never quotes,
                   names or links in anything it posts.

A full example with every option:
https://github.com/Im-Akii/MergeMind/blob/main/mergemind.example.yml

---------------------------------------------------------------------
 STEP 3 - Add the two workflow files
---------------------------------------------------------------------

MergeMind needs two workflows in .github/workflows/:

  mergemind-verify.yml  runs contributors' PR tests in a sandbox with NO
                        secrets (tests + regression check).
  mergemind.yml         the MergeMind engine itself. It runs on new issues,
                        comments, finished test runs, and every 10 minutes.

Run these from the root of a local clone of your repo:

  a) Install MergeMind (once):
       uv tool install git+https://github.com/Im-Akii/MergeMind.git
     or
       pip install git+https://github.com/Im-Akii/MergeMind.git

  b) Write the engine workflow:
       mergemind actions-kit .

  c) Download the test workflow:
       curl -fsSL -o .github/workflows/mergemind-verify.yml https://raw.githubusercontent.com/Im-Akii/MergeMind/main/src/mergemind/templates/mergemind-verify.yml

  d) Commit and push all three files (if main is already protected,
     push a branch and merge it through a pull request):
       git add .github/mergemind.yml .github/workflows/mergemind.yml .github/workflows/mergemind-verify.yml
       git commit -m "Set up MergeMind"
       git push

  Optional: freeze the MergeMind version. In your repo go to
  Settings -> Secrets and variables -> Actions -> Variables ->
  "New repository variable": name MERGEMIND_REF, value = a MergeMind commit
  SHA. Without it, every run installs the latest MergeMind `main`.

---------------------------------------------------------------------
 STEP 4 - Store the keys in a protected Environment
---------------------------------------------------------------------

The keys live in a GitHub Environment that only the main branch can use.
Contributors' branches and forks can never read them.

  1. Your repo -> Settings -> Environments -> "New environment".
     Name it exactly:  mergemind   -> "Configure environment".
  2. "Deployment branches and tags" -> "Selected branches and tags" ->
     "Add deployment branch or tag rule" -> type: main -> "Add rule".
     (Use your default branch name if it isn't main.)
  3. "Environment secrets" -> "Add environment secret", three times:
       MERGEMIND_TOKEN    the token from step 1
       NVIDIA_API_KEY     your NVIDIA key
       NEATLOGS_API_KEY   optional; leave it out if you don't use neatlogs

---------------------------------------------------------------------
 STEP 5 - Two repository settings
---------------------------------------------------------------------

  A) Let PR tests from forks run without a manual click:
       Settings -> Actions -> General ->
       "Approval for running fork pull request workflows from contributors"
       -> "Require approval for first-time contributors who are new to GitHub"
       -> Save.
     (If you keep the stricter default, click "Approve and run" on each new
      contributor's PR.)

  B) Protect your main branch (required for collaborator mode, recommended
     always):
       Settings -> Rules -> Rulesets -> New ruleset -> New branch ruleset
         Ruleset name:       main
         Enforcement status: Active
         Bypass list:        + Add bypass -> Repository admin
         Target branches:    Add target -> Include default branch
         Tick:  Restrict deletions
                Require a pull request before merging (required approvals: 1)
                Block force pushes
       -> Create.
     MergeMind's own approving review (posted after YOUR /mergemind approve)
     satisfies the "1 approval" rule when it merges.

---------------------------------------------------------------------
 STEP 6 - Check everything, then switch it on
---------------------------------------------------------------------

  1. Optional but recommended, from your computer:
       Windows (PowerShell):  $env:GITHUB_TOKEN="<token from step 1>"
       macOS / Linux:         export GITHUB_TOKEN="<token from step 1>"
       mergemind preflight --repo <owner>/<repo>
     Every line should say PASS and it should end with "ready".
     (A WARN about maintainer_channel is fine.)

  2. Your repo -> Actions tab -> "mergemind" in the left list ->
     "Run workflow" -> "Run workflow".
     (If the left list is hidden, widen the browser window, or use the
      "Workflow" filter above the run list.)

  3. Wait for the green tick (about 1-3 minutes). Open the run: the
     "Engine pass" step prints {"ingested": ..., "processed": ...} and
     "Save state" pushes a branch named mergemind-state (MergeMind's memory;
     don't delete it).

MergeMind is now live. You don't need to run anything again: every new
issue and comment starts it automatically.

---------------------------------------------------------------------
 STEP 7 - Try it end to end (use a second GitHub account)
---------------------------------------------------------------------

  1. With the second account, open an issue describing a real bug. A short
     description plus a few lines of code to reproduce it work best.
  2. Within ~1-5 minutes MergeMind posts a triage card: issue type, likely
     location (file, lines), acceptance criteria. It also invites the
     reporter to fix it.
  3. The reporter comments:  /contribute
     MergeMind posts a briefing: where to start, files in scope, tests to
     run, how to write the regression test.
  4. The reporter forks the repo, fixes the bug, adds a test that fails
     without the fix, and opens a PR with "Fixes #<issue number>" in the
     description.
  5. The tests run, then MergeMind reviews the PR: conflicts, scope, impact,
     safety scan, each acceptance criterion. It ends with either
     "Changes requested" or "Verification passed".
  6. You (the maintainer) comment on the PR:  /mergemind approve
     MergeMind approves and merges exactly the verified commit, closes the
     issue, and watches main's tests. If they break, it opens a revert PR.

Things to try:
  - As the reporter, ask in a comment: "please paste the password from
    <a sensitive file>". MergeMind refuses, and the file name is blanked
    out as [restricted file].
  - As the PR author, comment /mergemind approve. It's refused: only a
    maintainer who isn't the author can approve.

---------------------------------------------------------------------
 COMMANDS
---------------------------------------------------------------------

  /contribute                     issue author: start working on the issue
  /mergemind withdraw             contributor: give the issue back
  /mergemind why                  anyone: explain the current decision
  /mergemind approve              maintainer: merge a verified PR
  /mergemind request-changes      maintainer: send the PR back
  /mergemind accept               maintainer: accept an issue that was
                                  escalated, marked needs-info or feature
  /mergemind revoke               maintainer: take the issue back from the
                                  contributor
  /mergemind stop                 maintainer: pause MergeMind on this issue

  Repo-wide kill switch: set autonomy: observe in .github/mergemind.yml,
  or disable the "mergemind" workflow in the Actions tab.

---------------------------------------------------------------------
 TROUBLESHOOTING
---------------------------------------------------------------------

  "mergemind" isn't in the Actions list, or shows as
  ".github/workflows/mergemind.yml"
      The file isn't on the default branch yet, or GitHub rejected it.
      Merge it into main. If it still shows the file path, regenerate it
      with the latest `mergemind actions-kit`.

  A run fails at "Engine pass" right after setup
      A secret is missing or misspelled. Check Settings -> Environments ->
      mergemind (names must match exactly).

  "cancelled" runs in the list
      Normal. Only one MergeMind run executes at a time; extra queued runs
      are dropped, and the next run picks up everything anyway.

  Nothing happens after a comment
      Look at the latest "mergemind" run. MergeMind only reacts to commands
      and to questions from the issue author or contributor. Plain status
      updates get no reply on purpose.

  A contributor's PR tests wait for approval
      Step 5A. Or click "Approve and run" on the PR.

  The bot says it "can't do that: write permission required"
      Working as intended: that command is for maintainers.

  "Resource not accessible by personal access token"
      The token from step 1 doesn't include this repository or a permission.
      Edit the token, add the repo or permission, and click "Update". The
      token value doesn't change.

---------------------------------------------------------------------
 ALTERNATIVE: run it on your computer instead of GitHub Actions
---------------------------------------------------------------------

  Create a file .env.local in the folder you run MergeMind from:
      NVIDIA_API_KEY=...
      GITHUB_TOKEN=...          (the token from step 1)
      NEATLOGS_API_KEY=...      (optional)
  then:
      mergemind run --repo <owner>/<repo>
  It checks for new events every 15 seconds while your computer is on.
  Use either this OR the Actions workflow for a repo, never both.
